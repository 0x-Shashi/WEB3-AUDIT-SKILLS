# Security & Trust Model

## Overview

This document explains the security considerations for using this AI audit skill system.

---

## What This System IS

 **A knowledge enhancement layer** - Structured patterns that make AI more effective at finding vulnerabilities

 **Expert knowledge in readable format** - All patterns are in markdown, fully auditable

 **A force multiplier** - Helps auditors be more thorough and consistent

 **Open source** - All code and patterns are visible and verifiable

---

## What This System IS NOT

 **Not a replacement for human auditors** - AI assists, humans verify

 **Not a security guarantee** - No tool catches 100% of bugs

 **Not a black box** - Every pattern is readable and modifiable

 **Not collecting your code** - Everything runs locally in your IDE

## Security of the Skills Themselves

### Pattern Verification

Every vulnerability pattern in this system is:

1. **Sourced from real exploits** - Not theoretical, actually happened
2. **Documented with references** - Links to original findings
3. **Includes code examples** - Vulnerable vs secure code shown
4. **Community reviewed** - Open for scrutiny

### No Executable Code

```
Skills are ONLY markdown files containing:
- Text descriptions
- Code snippets (examples, not executed)
- Grep/regex patterns (run by your IDE, not us)
- Checklists

Skills contain NO:
- Executable binaries
- Scripts that run automatically
- Network requests
- File system modifications
```

### Verify Yourself

All skills are human-readable:
```bash
# View any skill
cat skills/solidity-scanner/SKILL.md

# Search for anything suspicious
grep -r "curl\|wget\|fetch\|http" skills/

# Count only markdown files
find skills/ -type f -name "*.md" | wc -l
```

## Security Limitations

### What AI Audits Can Miss

| Category | AI Strength | AI Weakness |
|----------|-------------|-------------|
| Known patterns |  Excellent | - |
| Business logic |  Moderate | Context-dependent |
| Novel attacks |  Moderate | No training data |
| Economic exploits |  Moderate | Requires simulation |
| Cross-contract |  Moderate | Context window limits |
| Timing attacks |  Poor | Needs runtime analysis |

### Recommended Workflow

```
1. AI Audit (This System)
    Quick coverage of known patterns
    Systematic checklist completion
    Initial finding generation

2. Static Analysis Tools
    Slither
    Mythril
    Echidna/Foundry fuzzing

3. Human Expert Review
    Business logic verification
    Economic attack analysis
    Final severity assessment

4. Formal Verification (Optional)
    For critical components
```

## Responsible Use Guidelines

### DO 

- Use as a first-pass audit tool
- Verify all findings manually
- Combine with other security tools
- Update skills with new patterns
- Share improvements with community

### DON'T 

- Rely solely on AI for security
- Skip human review of critical findings
- Assume 100% coverage
- Use for malicious purposes
- Claim AI audit = fully audited

## Incident Response

If a vulnerability is found in code that was "audited" with this system:

1. **Check if pattern existed** - Was it in our skill set?
2. **If yes** - Report false negative for improvement
3. **If no** - Add new pattern to prevent future misses
4. **Either way** - Remember AI audit  guarantee

## Privacy Considerations

### For Private Codebases

If auditing proprietary code:

1. **Review AI provider policies**
   - Claude: https://www.anthropic.com/privacy
   - OpenAI: https://openai.com/policies/privacy-policy

2. **Consider self-hosted options**
   - Local LLMs (Llama, etc.)
   - Private API deployments

3. **Sanitize if needed**
   - Remove sensitive comments
   - Anonymize variable names
   - Split into components

### Our Data Practices

We (the skill system maintainers):
- Do NOT collect your code
- Do NOT have analytics in skills
- Do NOT phone home
- Do NOT require accounts
